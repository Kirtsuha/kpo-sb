# 🎯 Общая идея решения
Разработано полнофункциональное банковское приложение для управления счетами, категориями и финансовыми операциями. Приложение демонстрирует применение современных принципов проектирования и архитектурных паттернов в Spring Boot приложении.

## 🔧 Дополнительный функционал:
- Гибкая система генерации ID с поддержкой multiple стратегий

- Импорт/экспорт данных в JSON, CSV, YAML форматах

- Продвинутая аналитика с финансовыми отчетами

- Кэширование данных через proxy-паттерн

- Автоматический пересчет балансов

- Командный интерфейс с декораторами

# 📊 Реализованный функционал
## Основные сущности:
- BankAccount - банковские счета

- Category - категории операций (доходы/расходы)

- Operation - финансовые операции

## Ключевые модули:
- Facade слои - упрощенный API для работы с сущностями

- ID Generation - стратегии генерации идентификаторов

- Analytics - финансовые отчеты и аналитика

- Import/Export - сериализация данных

- Cache Management - управление кэшированием

# ⚡ Принципы SOLID
## 1. SRP (Single Responsibility Principle)
- BankAccountFacade, CategoryFacade, OperationFacade - каждый отвечает за одну предметную область

- IdStrategy интерфейс - каждая стратегия отвечает только за генерацию ID

- ExportVisitor - отдельный класс для логики экспорта

## 2. OCP (Open-Closed Principle)
- IdGenerationContext - открыт для расширения (новые стратегии), закрыт для модификации

- ExportVisitor - можно добавлять новые форматы экспорта без изменения существующего кода

## 3. LSP (Liskov Substitution Principle)
- UUIDStrategy, TimestampIdStrategy, SequelIdStrategy - взаимозаменяемые реализации IdStrategy

- Все фасады могут быть заменены своими реализациями

## 4. ISP (Interface Segregation Principle)
- IdStrategy - минимальный интерфейс только для генерации ID

- Раздельные интерфейсы для разных аспектов системы

## 5. DIP (Dependency Inversion Principle)
- Внедрение зависимостей через конструкторы (@Autowired)

- IdGenerationContext зависит от абстракции IdStrategy, а не конкретных реализаций

# 🎯 Принципы GRASP
## 1. Information Expert
- BankAccount знает как создавать себя через фабричные методы

- Operation содержит логику валидации операций

## 2. Creator
- BankAccountFacade создает BankAccount

- CategoryFacade создает Category

- OperationFacade создает Operation

## 3. Controller
- ConsoleApplication - основной контроллер приложения

- Фасады выступают как контроллеры для своих доменных областей

## 4. Low Coupling
- Слабая связность между модулями через фасады

- IdGenerationContext изолирует стратегии от клиентов

## 5. High Cohesion
- Каждый фасад имеет высокую связность внутри своей предметной области

- Стратегии генерации ID сгруппированы по назначению

# 🏗️ Паттерны GoF
## 1. Strategy (IdStrategy)
- Классы: IdStrategy, UUIDStrategy, TimestampIdStrategy, SequelIdStrategy

- Важность: Позволяет динамически выбирать алгоритм генерации ID в runtime

- Применение: Конфигурируется через application.properties

## 2. Factory Method (Фабричные методы в доменных сущностях)
- Классы: BankAccount.create(), Category.create(), Operation.create()

- Важность: Инкапсулирует логику создания объектов, обеспечивает согласованность

- Применение: Создание сущностей с автоматической генерацией ID

## 3. Facade (Фасады сервисов)
- Классы: BankAccountFacade, CategoryFacade, OperationFacade, AnalyticsFacade

- Важность: Упрощает сложные подсистемы, предоставляет единый интерфейс

- Применение: Упрощение работы с репозиториями и сервисами

## 4. Proxy (Кэширующие прокси)
- Классы: BankAccountRepositoryProxy, OperationRepositoryProxy

- Важность: Прозрачное добавление кэширования без изменения бизнес-логики

- Применение: Ускорение доступа к часто используемым данным

## 5. Command (Команды для аналитики)
- Классы: FinancialSummaryCommand, CategorySummaryCommand

- Важность: Инкапсулирует запросы как объекты, поддерживает отмену и логирование

- Применение: Выполнение аналитических отчетов

## 6. Decorator (Декораторы команд)
- Классы: TimingCommandDecorator

- Важность: Динамическое добавление функциональности (измерение времени выполнения)

- Применение: Мониторинг производительности команд

## 7. Visitor (Экспорт данных)
- Классы: ExportVisitor, JsonExportVisitor, CsvExportVisitor, YamlExportVisitor

- Важность: Отделение алгоритмов экспорта от структуры объектов

- Применение: Поддержка multiple форматов экспорта

## 8. Template Method (Импорт/экспорт)
- Классы: AbstractDataExporter, AbstractDataImporter

- Важность: Определяет скелет алгоритма, позволяя подклассам переопределять certain шаги

- Применение: Единый процесс импорта/экспорта для разных форматов

# 🚀 Инструкция по запуску
## Предварительные требования:
- Java 17 или выше

- Gradle 8.x

- Spring Boot 3.x

# Шаги для запуска:
## 1. Клонирование репозитория

```bash
git clone <repository-url>
cd Finance
```
## 2. Сборка проекта


```bash
./gradlew build
```

## 3. Запуск приложения

```bash
./gradlew bootRun
```
или

```bash
java -jar build/libs/finance-app.jar
```
## 4. Использование

- После запуска откроется консольное меню

- Следуйте инструкциям на экране

- Доступны демонстрации всех паттернов и функциональности

# Конфигурация:
Файл application.properties позволяет настроить:

- Стратегии генерации ID для разных сущностей

- Настройки базы данных H2

- Параметры кэширования

## Демонстрационные возможности:
- Управление счетами - создание, просмотр, обновление счетов

- Операции - доходы и расходы по категориям

- Аналитика - финансовые отчеты и статистика

- Импорт/экспорт - работа с JSON, CSV, YAML
 
- Кэширование - демонстрация proxy-паттерна

# 🎉 Заключение
Приложение успешно демонстрирует применение современных принципов проектирования и архитектурных паттернов. Гибкая архитектура позволяет легко расширять функциональность и адаптировать систему под changing требования.
